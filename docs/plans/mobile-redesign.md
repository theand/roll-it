# 휴대폰·태블릿 화면 개선

사용자 요청: 기존 윷·2D·3D 사이트의 디자인, 효과, 기능을 개선한다.
주요 기기는 휴대폰과 태블릿이다. 사용자 재지시에 따라 이미지 시안 선택을
생략하고 실제 화면을 바로 구현한다.

## 범위와 복잡도

세 진입점과 정적 파일 구조를 유지한다. 최소 흐름은 모드 선택 → 던지기 →
결과·최근 기록 확인 → 다시 던지기다. 서버, 새 패키지, 계정, 네트워크 저장은
추가하지 않는다. 각 페이지가 자기 탭의 sessionStorage에 최근 30회만 저장한다.
저장이 거부되어도 던지기는 계속 가능하다. 3D의 Dice 구현과 아카이브 사본은
바꾸지 않고 main.js에서 표시·조명·배치만 조정한다.

## Direction contract

THESIS: 주사위와 윷을 놓는 청록색 놀이 공간을 세 모드의 공통 중심으로 삼는다.
소개 화면 없이 바로 던질 수 있어야 한다.

OWN-WORLD: 옅은 민트 바탕, 짙은 청록색 놀이 공간, 크림색 윷·주사위,
살구색 큰 실행 버튼. 시스템 한글 글꼴과 명확한 터치 컨트롤을 쓴다.

STORY: 모드를 고르고, 결과를 크게 읽고, 이전 기록과 비교하고 다시 던진다.
윷의 추가 턴과 빽도, 2D 더블, 3D 개별 값과 합계를 구별한다.

FIRST VIEWPORT: 휴대폰에서는 브랜드·모드 탭·제목·놀이 공간·컨트롤이
수직으로 이어진다. 태블릿에서는 놀이 공간 옆에 기록을 둔다. 작은 휴대폰에서도
주 실행 버튼은 최초 화면 안에 들어간다. 물체의 회전과 착지, 결과의 짧은 등장만
움직이며 reduced-motion에서는 결과를 빠르게 확정한다.

FORM: 사용자 재지시에 따라 바로 구현하는 방향. 이전 탐색 seed f659a49d는
시안 선택에 사용하지 않았다. 방향 승인 절차로 다시 작업을 멈추지 않는다.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 검증

`tests/browser-smoke.py`는 browser-cdp-pw harness에서 실행한다.
저장소 루트를 127.0.0.1:3460에서 서비스한 뒤 다음 명령을 실행한다.

```bash
browser-cdp-pw run < tests/browser-smoke.py
```

윷 16가지 판정, 연속 던지기와 기록 상한, 기록 복원·삭제, 2D 더블·합계,
3D 네 면 종류를 4개씩 굴리기, 정상 애니메이션 완료, 저장값 오염·거부,
휴대폰과 태블릿의 레이아웃·터치 영역을 확인한다.
화면 증거는 `/tmp/roll-it-review/`에 저장한다. 실기기 터치·햅틱은 별도 확인이 필요하다.

## 완료 증거

- 브라우저 검사: `--- 57 passed, 0 failed ---`.
- 세 모드 × 390×844, 834×1112, 1194×834, 320×740 화면 검수.
- 모듈 로딩 실패를 별도로 주입해 3D 컨트롤 비활성화 및 2D 링크 전환 확인.
- 인라인 스크립트와 main.js 구문 검사, `git diff --check` 통과.
- Dice 클래스와 아카이브 사본 바이트 동일. 물리 클래스는 수정하지 않았다.
- 독립 화면 검수에서 실행 버튼의 단단한 그림자만 지적되었으며, 세 화면에
  부드러운 그림자를 적용하고 재검수에서 해당 항목 해결 판정을 받았다.
- detector의 접촉 그림자 경고는 실제 렌더 검수에서 네온 효과가 아닌
  물체의 깊이 표현으로 확인되어 유지했다.
- Safari 실기기와 햅틱은 미검증이다.
